# Private account access

Dome11 remains the owner. Additional accounts, including UserTest, are created only through owner/service-authorized invitations. No public registration or paid identity provider. Existing owner records, session signatures and service credentials are preserved.
Owner sets a password using the one-time setup link (fragment token, removed from address bar immediately). The server requires a 256-bit setup token, checks its SHA-256 digest and expiry, and creates the owner record atomically in a strong-consistency Blob store. The token cannot replace an existing account. Member invitations use a separate 256-bit, 48-hour, one-time token whose digest is stored in a strong-consistency Blob store. Acceptance atomically creates a username-specific record; the token is removed from the address bar and submitted only in the JSON request body. Concurrent acceptance cannot overwrite an account. Only the owner or authorized internal service can issue/revoke accounts; members can change only their own password. Disabled accounts cannot log in, and their sessions expire from the account cache within 30 seconds. Passwords use salted scrypt; no password or session is stored in client localStorage.

An HttpOnly, Secure, SameSite=Strict, host-only session cookie remembers login for 30 days. Unchecked remember-me creates a browser-session cookie with a 24-hour server expiry. Settings allows logout and password changes; changing the password invalidates other sessions within the 30-second account-record cache interval. POST authentication actions require same-origin requests. Native Netlify per-IP/domain limits restrict login and API traffic. Limits mitigate abuse; they do not provide an absolute account-wide traffic cap.

The frontend gates app mounting and data polling until authenticated. APIs and image functions check authorization before reading football sources, including direct function routes. CDN caching is disabled for protected responses; server-side saved-response caching remains. Images can use private browser caching. The public app shell, logos and bundled public football seed assets remain public; this is private authenticated interactive app/API access, not encryption of public football facts or retroactive protection of old deployments.

Scheduled jobs use the existing x-touchline-refresh credential independently of owner sessions. scripts/private-request.py loads it from the runtime environment or the existing protected credential file; never place credentials in job prompts, URLs, source archives or output. If that runtime credential file is lost, restore authorized server access before running the jobs. Changing the owner's password or signing out does not rotate the service credential.

Deploy secrets: TOUCHLINE_REFRESH_SECRET (also derives the session signing key), TOUCHLINE_SETUP_HASH and TOUCHLINE_SETUP_EXPIRES. The deployment helper keeps the actual setup token outside the source archive. Preserve the refresh secret across deployments. No payment method, paid plan, or billing setting is changed.
